## 2. 一次翻译的完整旅程

```
侧栏 TranslatePanel.submit()
  └─ splitSegments(text)                      // 长文切段
  └─ useJob.run()                             // 生成 requestId，Port 发 translate
        ↓
Service Worker: chrome.runtime.onConnect     // background/index.ts
  └─ handleJobMessage()                      // background/jobs.ts
  └─ loadSettings()                          // storage/settings.ts
  └─ translateWithFallback(settings, engine) // core/engine.ts
        ├─ makeCacheKey → getCached          // core/cache.ts
        ├─ resolveEngine(engineId)           // core/providers/registry.ts
        │     └─ createAiProvider / createGoogleFreeProvider / createMyMemoryProvider
        │           └─ fetchWithTimeout → ensureOk → 解析
        └─ 失败则按 fallbackEngineIds 换免费通道再试
  └─ 每次 onDelta → port.postMessage({kind:'delta'})
  └─ 成功 → postMessage({kind:'done'}) + addHistory()
        ↓
侧栏 useJob.onMessage → setState → 界面渲染
```

检查与润色的旅程（M2）：

```
侧栏 TranslatePanel.startCheck() / startPolish()
  └─ Port: {kind:'check', text} / {kind:'polish', text, instruction}
        ↓
Service Worker
  ├─ check:  splitForCheck(text)                → 每段 runCheckChunk()
  │            └─ AI 返回 {issues:[quote/replacement/...]}
  │            └─ locateIssues() 三级定位 → mergeIssues() → applyIssues()
  │            └─ progress 事件（第几段/共几段）→ checkDone
  └─ polish: runPolish() 流式 → delta → polishDone
        ↓
CheckView：issueMarks() 生成「划掉 + 绿色改法」；忽略集合决定终稿
PolishView：diffMarks(原文, 润色稿) 生成合并视图；changeEntries() 生成修改清单
```

划词的旅程（M3）：

```
网页里鼠标选中文字
  └─ content/selection.ts 在 mouseup（捕获阶段）读选区
        ├─ 在输入框 / contenteditable 里 → 直接忽略
        ├─ readSelectionInfo()：文字 + 语境（标题 + 网站 + 所在块前后 N 字符）
        └─ 在选区旁显示「译」小图标（Shadow DOM）
              ↓ 点击图标
        content/translate-client.ts 建 Port，发 {kind:'translate', segments:[文字], context}
              ↓
        Service Worker 复用 jobs.ts / engine.ts（与面板完全同一条链路）
              ↓ delta / done / error
        气泡：流式显示译文 → 朗读 / 复制 / 重试 / 关闭
```

网页翻译的旅程（M4）：

```
面板底部「翻译本页」/ 右键菜单 / Alt+P
  └─ app/PageButton.tsx → runtime.sendMessage({type:'yuyi:page-command', command:'translate'})
        └─ SW background/page.ts → chrome.tabs.query({active:true}) → tabs.sendMessage
              └─ content/index.ts → page/translate.ts startPageTranslation()
                    ├─ page/collect.ts 采集单元（跳过代码/输入框/隐藏/已译/目标语言）
                    ├─ page/text.ts 分批（8 段 / 1200 字符）
                    ├─ 批次 ×2 → translate-client.ts（silent：不写历史）
                    │      └─ SW jobs.ts → engine.ts 缓存 → 主引擎 → 失败降级
                    │            └─ done.segments → page/render.ts 写入 span[data-yuyi="trans"]
                    ├─ page/pill.ts 状态条 + runtime.sendMessage({type:'yuyi:page-state'}) 广播回面板
                    └─ MutationObserver（500ms 防抖）→ 新增节点里挑单元 → 继续补译
```

网页翻译的几个设计点：

- **采集单元**是「不含块级子元素的块级元素」：`<p>`、`<li>`、`<h2>`、`<td>` 各算一段；`<div><p>…</p></div>` 会继续往下切，不会把整块当一个段落。
- **写入用追加/搬移，不改 `innerHTML`**：双语是往元素末尾追加译文 span；仅译文是把原有子节点整体搬进 `[data-yuyi="orig"]` 隐藏，还原时搬回去，所以还原后 DOM 与翻译前一致（有单测比对 `innerHTML`）。
- **不写历史**：一次翻页会产生 5–10 个批次，写历史会灌爆 `history.v1`，所以请求带 `silent: true`。
- **观察器必须过滤自己的节点**：译文 span 也带 `data-yuyi`，`pickScanRoots()` 会把它们跳过，否则会自己触发自己、无限翻译。
- **SPA 换页靠 URL 比对**：隔离世界里的 `history.pushState` 补丁看不到页面调用，所以用 `location.href` 变化触发整页重扫。

几个设计点：

- **requestId 是唯一线索**：面板生成，SW 原样带回；面板只认自己当前的 requestId，避免旧请求串台。
- **降级不污染流式**：只有主引擎收到的 delta 会推送；降级后的结果以 `done` 整体覆盖。
- **缓存在 SW 里**：面板关闭后 SW 可能被回收，但缓存对象已经落盘到 `storage.local`。

## 3. 设置是怎么存的

- 结构定义在 `src/storage/settings.ts`（`Settings` 类型 + `DEFAULT_SETTINGS`）。
- 任何页面 `loadSettings()` 都拿到补齐默认值后的完整对象（`normalizeSettings`）。
- 设置页每次改动都调 `patchSettings()` 写回；输入框有 400ms 防抖（`options/App.tsx`）。
- 面板只改语言与引擎，也是同一个 `patchSettings`。

## 4. 历史

`src/storage/history.ts`：一个数组放 `history.v1`，最新在前，最多 200 条，单条文本截断到 4000 字符。历史开关关掉后 `addHistory` 直接跳过。

## 5. 剩下的里程碑长在哪

- **M5 学习**：`src/storage/learning.ts` + `src/learning/` 页面；收藏入口加在气泡和面板结果区。

M4 已经落地的部分：

- 采集/写回/编排在 `src/content/page/`（`text` / `collect` / `render` / `translate` / `pill`）；可测的纯函数集中在 `text.ts`，DOM 采集与写入在 `collect.ts` / `render.ts`，由 `tests/page-helpers.test.ts`、`tests/page-render.test.ts` 覆盖。

- 面板只负责发命令与显示状态：`src/app/PageButton.tsx` + `src/background/page.ts`，翻译本身全在 content script 里发起。

- 划词逻辑在 `src/content/{selection,bubble,context,translate-client}.ts`；可测的纯函数都在 `context.ts`（`looksLikeWord` / `buildContextWindow` / `composeContext` / `calculatePlacement`），由 `tests/selection-helpers.test.ts` 覆盖。
- 气泡是 Shadow DOM + 字符串样式，不引 React；翻译复用同一条 Port 协议，SW 侧不需要新代码。
- 图标/气泡的位置计算在 `calculatePlacement`：上方放不下翻下方，贴边收进视口。

M2 已经落地的部分（照着改就行）：

- 检查提示词在 `src/core/providers/ai/prompts.ts` 的 `buildCheckMessages`，JSON 校验与定位在 `src/core/check.ts`。
- 润色提示词在 `buildPolishMessages`，方向拼装在 `src/core/polish.ts` 的 `buildPolishInstruction`。
- 视觉部分是 `src/app/CheckView.tsx` / `PolishView.tsx` + `src/app/marks/MarksView.tsx`，样式在 `theme.css` 的 `.mark-*` 与 `.issue-*`。

## 6. 为什么这样分层

- `core/` 里没有 `chrome.*` 之外的浏览器依赖，也没有 React —— 这样能被单测直接跑（`tests/` 里的 136 个测试是 core 层 + mock AI 链路 + 组件静态渲染 + 划词与网页翻译的 DOM 纯函数/渲染往返）。
- `content/context.ts`、`content/page/text.ts`、`content/ui-mark.ts` 是纯函数或纯 DOM 辅助，逻辑优先写进这几处；`content/page/collect.ts`、`render.ts` 在 happy-dom 里也能直接测（构造 fixture → 采集 → 写入 → 还原）。
- `storage/` 是唯一碰 `chrome.storage` 的地方，且在测试环境里会退化到内存 Map（`storage/local.ts`）。
- `app/` 与 `sidepanel/` 分开，是为了以后设置页也能复用同一个翻译面板组件。
