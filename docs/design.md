# 羽译 设计大纲

> 状态：M0–M7 全部实现。本文件是产品与技术的总纲；工程约定见根目录 `AGENTS.md`，服务商对接细节见 `providers.md`。维护与同步规则见 [README.md](README.md)。

## 1. 定位

把「翻译 → 检查 → 润色 → 记住」做成一条线：AI 负责语境与表达，传统机器翻译负责快与便宜，所有修改都以**可读的荧光笔标注**呈现。

差异化（对比划词翻译、沉浸式翻译、沙拉查词）：

| 维度 | 竞品常见做法 | 羽译取舍 |
|---|---|---|
| 多引擎 | 十几个引擎 + 对比 | 默认只保留可靠的 AI + 两个免费兜底；翻译面板可勾选、可拖动排序的多个引擎并列对照，排在第一位的作为主引擎 |
| 检查/润色 | 另开工具或不做 | 和翻译在同一个面板里做完，修改用荧光笔 diff 展示 |
| 划词 | 词典卡为主 | 默认带上下文（所在段落 + 标题链 + 相邻段 + 列表/表格，可切整页大纲）交给 AI 理解 |
| 学习 | 生词本 | 收藏即进复习闭环（SRS），把翻译变成学习入口 |

## 2. 功能大纲

### 2.1 翻译（已实现）
- 语言栏：源语言自动检测 → 目标语言；目标默认「智能」（其他语言译成中文、中文译成英文，按书写系统判断），也可固定某个语言，固定时才可互换；语言选择持久化。
- 输入：多行文本；`Enter` 直接翻译（`Shift+Enter` 换行），超过 2500 字符按段落自动切段；打开弹窗即聚焦输入框。
- 三动作：翻译 / 检查 / 润色，共用同一份输入。
- 结果：AI 流式输出；显示引擎、耗时、缓存命中；引擎可多选，句子翻译时每家的译文并列成卡（查词典仍只出一张词典卡）；复制、清空、历史回看。
- 术语表：设置里维护 `原文 → 译文`，注入提示词。

### 2.2 语法检查（已实现 M2）
- 输出结构化 `issues[]`（`quote` / `replacement` / `category` / `severity` / `explanation`）。
- 偏移量不可信：模型只给 `quote`，前端三级定位（精确 → 忽略大小写 → 忽略空白），定位失败计入 `dropped` 并在 UI 明示。
- 视图：**高亮**（原文划掉 + 绿色改法，就是 git diff 的读法）、**列表**（逐条问题卡片）、**终稿**（应用所有未忽略的修改）。
- 交互：每条可以「忽略 / 恢复改动」；被忽略的片段变灰虚线、保留原文；「复制终稿 / 替换输入」把结果送回去。
- 长文：`splitForCheck()` 按 1400 字符切段、保留全文 offset，逐段检查后按全局位置合并去重叠。

### 2.3 润色（已实现 M2）
- 方向控制两层叠加：
  - 快捷 chips：更自然 / 更正式 / 更口语 / **更诗意** / 更简洁 / 更学术 / 保留术语 / 尽量不改长度。
  - 自由指令框：一句话说清要求（例：「改得像散文，保留全部事实」），直接进提示词。
- 视图：内联合并视图（红底删除线 = 删掉，绿底 = 新增，未动普通字）、纯净稿、并排对照（窗口窄于 560px 时自动禁用并排）。
- diff 与修改清单都由前端计算（`diff` + `Intl.Segmenter`），模型只输出润色后的全文；模型给理由需要多一次调用，留到后续版本。
- 「再来一版」：同文本重新采样，界面保留当前结果直到新版返回。

### 2.4 划词翻译（已实现 M3；选区来源已统一）
- 触发：选中出现小图标（可关）/ `Alt+T` / 右键菜单。触发信号汇合到一处：`mouseup`（立即）、`selectionchange`（140ms 防抖，键盘与触摸选区靠它）、`pointerdown`（指针按住期间不响应，避免拖选途中乱闪）。所以鼠标拖选、双击、三击、`Shift+方向键`、触摸长按都能出图标。
- 选区来源：三种读法按顺序尝试，共用同一条管线——原生 `window.getSelection()` 的 Range / Shadow DOM（拖动过程中从 `pointerdown`、`pointermove`、`mouseup` 的 `composedPath` 累计 open `ShadowRoot`，用 `getComposedRanges()` 重建 Range；重建不出文字时用 `selection.toString()` 兜底，位置退回鼠标点）/ `<input>`·`<textarea>` 的 `selectionStart/End`。输入框与 `contenteditable` 编辑器都参与，`type=password` 与数字/日期类控件不参与。iframe 里也生效：content script 注入所有框架（`all_frames: true`），每个帧各自处理自己的选区；网页翻译仍只在主框架执行。
- 气泡：Shadow DOM 挂载、`all: initial` 隔离。所有句子翻译（单引擎也一样）都渲染成 `.engine-result` 小卡，按引擎勾选顺序排列：卡头是服务名与状态点，下面是该引擎的译文；每张卡右上角有朗读、复制、收藏三个 22px 纯图标动作（鼠标停留用 `title` 说明用途，复制与收藏成功后变对勾），AI 服务卡另有「扩上下文」图标（按页范围重译），不再有单独的底栏动作区；加载时提示「正在用 N 个引擎翻译」（单个为「正在翻译」），卡内流式追加，失败的卡只标红自己。单词与词典卡仍保留底栏的引擎、耗时与朗读、复制、收藏；整句完成的底栏只剩「上下文预览」，点开显示本次实际发出的上下文（命中缓存时卡内标「缓存命中」）。气泡头部整条可拖动，关闭只有右上角一个入口；正文可拖选复制（`user-select: text`，不受宿主页 `user-select: none` 影响），选中高亮也由气泡自己声明（宿主页的 `::selection` 会漏进 Shadow DOM）；选区文本保留换行（行内空白压成单空格、最多留一个空行），译文与原文分段对齐；流式只追加节点，边生成边选不被打断。宽度按选区矩形宽加卡片内边距（`BUBBLE_WIDTH_EXTRA = 56`，正文比选区宽约 8px），下限 240，上限视口宽度的二分之一（视口窄到不足 240 时保留下限；拿不到宽度时 340），滚动与缩放时随选区重算，所以同一段的译文行宽与原文接近；宽度不足 300px 时底栏动作收成纯文字（用于单词/词典卡，整句卡没有底栏动作）。查词命中词典时固定用默认宽度 340（短词选区不把词卡挤窄），见 2.8。划词与弹窗共用设置里的同一组引擎（「翻译与划词」槽位），每张卡的朗读、复制、收藏只作用于自己那份译文，历史仍只记主引擎一条；词典查询仍只出一张卡。
- 视觉分层：卡片底是 `--surface`，译文区垫 `--brand-soft`（深浅两套都走主题变量），让译文内容从头部与底栏里分出来；错误态不铺底，交给 `--danger-soft` 图标表达。
- 上下文：页面标题 + 网站 + 选区所在块前后各约 N 字符（默认 600，可在设置里改；设为 0 时只带标题与网站），再按「上下文范围」装配结构（`segment` 仅段落窗口；`section` 默认，加章节标题链、相邻段落的末两句/首两句（跳过 nav / aside / footer / pre / code 等噪音与外语段落）、列表前四项、表格表头与本行；`page` 再加页面大纲与首段，不整页入 prompt）。`src/content/structure.ts` 负责结构采集与预算装配，总预算 2000 字，优先级即装配顺序，超出截断并标 `…`；窗口按选区文本在块里定位（先精确匹配，再忽略大小写），被截断的一侧标 `…`；跨块选区改取起点块到终点块之间的窗口，仍定位不到（页面改写过选区）就不带段落窗口，不再退回块开头拿无关内容充数。上下文只用于消除歧义（多义词选义项、代词找指代、术语用法、语气与领域），不进译文。输入框来源没有段落可读，按 `aria-labelledby` / `aria-label` / `label[for]` / 包裹 `label` / 占位符 / `fieldset legend` 的顺序找标签；iframe 用同源顶层窗口的标题与域名。选区超过 2000 字时照常翻译，但上下文只保留标题与网站。完成态的 AI 结果卡右上角有「扩上下文」图标，点它改用整页范围重译一次（范围已是 `page`、单词/词典卡或选区超过 2000 字时不出现）。
- 单词与句子共用一套气泡，单词模式放大原词显示；单词/词典卡的底栏有「收藏」，整句卡则用右上角的收藏图标，把词句连同译文、页面标题与来源收进生词本（M5）。单词在词典服务可用时直接查词典、展示音标与释义（见 2.8），不再把词当句子翻译；AI 讲解不做。
- 定位：图标出现在光标右下角，键盘/触摸选区没有光标时取选区末端；气泡默认贴在选区下方、不遮挡原文，放不下才翻到上方并贴边修正；滚动 / 缩放时跟随，拖动后改为固定位置（关闭重开恢复跟随），选区失效就关闭。全屏时图标与气泡改挂到 `document.fullscreenElement` 里，否则 top layer 之外的元素不会渲染。
- 边界（拿不到选区，不覆盖）：closed shadow root、canvas 自绘文字（Google Docs / Figma / Office 网页版）、`edge://` 等浏览器内置页与内置 PDF 查看器、扩展商店、以及站点自己禁止选择或清空选区的页面。

### 2.5 网页翻译（已实现 M4）
- 入口：弹窗底部「翻译本页」/ 右键菜单「羽译：翻译此页」/ `Alt+P`；页内右下角有状态条（进度 / 取消 / 重试失败 / 还原本页）。
- 采集：从 `document.body` 递归，只把「不含块级子元素的块级元素」当一个单元（段落、标题、列表项、表格单元格）；`<br>` 读成空格，不用 `textContent` 直接拼接（会把 `Hello<br>world` 粘成 `Helloworld`）。
- 跳过：代码块（`pre/code` 等）、输入框、`contenteditable`、`translate="no"`、`.notranslate`、隐藏内容、我们自己写入的节点；已是目标语言的段落（按脚本判断，中 / 日 / 韩 / 俄 / 阿可靠；拉丁语系目标不跳过）。目标语言为「智能」时，采集后先用前 12 段拼样本定一次方向，再据此过滤已是目标语言的段落——整页只解析一次，避免同一页的批次被翻成不同语言。
- 分块：8 段 / 1200 字符一批、2 批并发；单元文本超过 3000 字符直接跳过并在状态条说明。
- 呈现：**双语对照**（原文块末尾追加 `span[data-yuyi="trans"]`）与**仅译文**（原文子节点整体搬进 `span[data-yuyi="orig"]` 隐藏，还原时搬回）——都不销毁页面原有节点；译文与原文完全相同时不插重复段。
- 动态内容：首次翻译后挂 `MutationObserver`（`childList` + 500ms 防抖），只扫新增节点，并过滤自己的译文（否则会自己触发自己）；`location.href` 变化（SPA 换页）时整页重扫。单页上限 400 段。
- 失败与取消：一批失败只标记那一批（虚线框）并计入失败数，其余照常；取消立即停发新批次、已译保留；还原删掉全部译文与标记，DOM 回到翻译前。
- 不写历史：网页翻译用 `silent` 标记跳过 `history.v1`，否则翻一页会灌 5–10 条记录。
- 未做（留后）：按域名的站点规则（`never/auto/manual` + 单站目标语言）、占位符保护（链接与加粗不进入译文）、iframe 与 shadow DOM 内文本、单段重译。

### 2.6 学习（已实现 M5）
- 收藏入口两个：划词气泡底栏「收藏」（带原文、译文、页面标题、来源 URL、语言对；单词把词典服务返回的 `DictionaryEntry` 存成结构化快照——音标、释义、英英释义、词形、例句、词组六类，条数与长度都有上限；句子存译文）与弹窗翻译结果卡「收藏」。两条入口都不保存上下文引文（卡片没有 `context` 字段，旧数据读入即丢弃）。同一 `原文 + 目标语言` 视为一张卡，重复收藏直接跳过（返回已有卡、不写入）；导入同样按这一对去重。
- 生词本页面（新标签页）：顶部四项统计（今日新增 / 待复习 / 连续天数 / 正确率），下面是卡片列表（原文；单词卡有词典快照时改渲染音标/释义/词形/例句富卡片，没有快照才退回纯文本译文；来源域名与时间、复习次数），支持单张删除、整体清空（确认）。
- 复习：简化 SM-2，字段 `ease / interval / dueAt / reps / lapses`，一次最多 20 张。复习台先只给原文，点「显示答案」出译文，再按四档评分（忘记了 / 有点难 / 记得 / 很简单）算下一次到期时间；「忘记了」10 分钟后再出现。
- 统计：只记复习次数（按天）与正确次数，正确率 = 正确 / 总复习；连续天数含今天与昨天两种起点。
- 数据：`chrome.storage.local` 的 `learning.v1`，导入导出 JSON；导入只并卡片、不并统计，重复项跳过，不做多设备同步。
- 拍板结论：**词与句都能收**（学习目标兼顾背词与积累表达）；**不做 AI 例句**（v1 不额外花 Key）；复习强度固定 20 张、四档评分；不做云同步。生词本单词卡直接展示词典服务返回的音标、词性与例句（存的是收藏时的结构化快照，旧卡无法回填）。

### 2.7 设置页（已实现，v4 顶栏分类）
顶栏 6 个分类，一屏只显示一类：**通用**（主题/语言/历史）、**翻译**（划词触发、上下文范围与长度 / 网页翻译呈现方式）、**词典**（单词查词典开关、词典服务、六项展示内容）、**引擎**（四个槽位分配：翻译面板可多选、其余单选，旁边标可用状态与去配置）、**服务**（免费通道开关、百度/微软凭证、AI 服务增删改与测试——详情里设模型、温度、思考强度；点进单个服务看申请步骤与额度）、**其它**（清缓存/历史、恢复默认、快捷键、版本）。引擎与服务分离：引擎只做分配，服务只做配置。

### 2.8 词典查询（已实现 M7）
- 判据：输入或选区是单个词——1–40 个拉丁字母（可带撇号与连字符）或 1–4 个汉字，两端标点先裁掉（`parseDictionaryQuery()` 返回 `en-zh` / `zh-en` 方向）；开关关闭、或当前服务不支持该方向（英英词典查中文词）时走翻译，长句与段落始终走翻译。
- 服务：`src/core/providers/dict/` 下两个免 Key 实现——有道词典 `dict.youdao.com/jsonapi`（英→中走 `ec`：音标 + 英美发音、中文释义、英英释义、词形变化、双语例句、常用词组；中→英走 `ce`：拼音 + 发音、英文对应词）与 Free Dictionary API（英英释义、音标、例句，仅英→中）。服务定义在 `providers/dict/services.ts`，各自带 `capabilities` 与 `supportsChinese`，设置页据此禁用当前服务不提供的展示项。
- 数据：`DictionaryEntry`（`direction` + `phonetics / translations / definitions / forms / examples / phrases`）+ `settings.dictionary`（开关、服务、六个展示开关）；展示开关只影响呈现，不影响抓取。中文词条复用同一结构：`direction: 'zh-en'`，`translations` 放英文对应词，`phonetics` 是拼音，例句是「中文原句 + 英文译文」，所以卡片只需把释义标题从「中文释义」换成「英文释义」。
- 回退：词典未收录（适配器返回 `null`）或请求失败时，静默改用主引擎（`primaryTranslateEngine()`）翻译，并在 `JobResult.notice` 里带一句说明；这是唯一允许的降级，只作用于查词。
- 缓存：SW 内存 Map，键 `服务:小写词`，TTL 24 小时、上限 200 条，不落盘（词条体量大，且丢了重查成本低）。
- 发音：有道用 `dictvoice?audio=<词>&type=1|2`（英式 / 美式）直接播；无音频或播放失败时退回 `speechSynthesis`。气泡里的播放受宿主页 CSP 影响，弹窗不受影响（待验证：`media-src` 白名单站点）。

## 3. 荧光笔标注规范（M2 的核心）

统一数据结构：

```
Mark = { kind: 'equal'|'del'|'ins'|'warn', text, issueId?, severity?, state? }
```

- 检查：问题片段默认就是 `del`（红/黄按 severity 上色 + 删除线），紧跟 `ins`（绿底）给出改法；点「忽略」后变 `warn`（灰虚线、不删除）。
- 润色：`diff` 算出 `del/ins/equal`，与检查同一套渲染。
- 颜色语义固定：红 = 错误，黄 = 警告/建议，绿 = 修改后，灰 = 已忽略。
- 不只靠颜色：错误加波浪下划线、已忽略加虚线、删除线表示被删。
- 高亮 / 纯净切换；窄栏读不动时用列表视图或终稿兜底。

## 4. UI/UX

- 载体：**只有工具栏弹窗一个界面**（`action.default_popup`，340×600，点到别处就关），设置页与生词本仍是新标签页；划词气泡与网页译文注入在页面内，网页翻译的进度条固定在页面右下角（Shadow DOM，`data-yuyi-ui="pill"`）。
- 弹窗布局：头部（品牌 · 翻译/历史 tab · 生词本 · 设置）→ 设置条（语言两枚胶囊 + 交换 + 引擎多选）→ 输入卡（三个动作在框内右下角：检查 / 润色 / 翻译）→「润色方向」折叠块 → 结果卡片（内部滚动，复制/清空沉到卡片底部）→ 底部（翻译本页 · 版本）。
- 高度固定、内容自己滚：检查的高亮/列表/终稿与润色 diff 都塞进结果卡片里滚，不再另开页面；代价是弹窗一关就看不到过程（任务会跑完并进历史），且「并排对照」需要 560px 以上宽度，在 340px 的弹窗里始终不可用。
- 视觉语言（v1「柔光」）：白纸卡片 + 柔和阴影 + 大圆角（10/14/20），主色羽蓝 `#4F6BF0` 只用于品牌标记、主按钮、选区与激活态；深色是独立配色（降饱和、主色提亮、输入框比卡片更暗、主按钮改深字）。气泡是唯一保留轻微回弹的动效，其余动效只表达状态。完整规范（变量表、组件、三处界面尺寸、动效与验收清单）见 [ui-design.md](ui-design.md)。
- 主题：`settings.theme`（auto/light/dark）→ 扩展页面写 `data-theme`；页面内的气泡、触发图标、状态条是 Shadow DOM，变量由 `src/content/theme.ts` 在 `:host` 上重新声明，所以 `theme.css` 与它必须同步修改。
- 交互底线：所有请求有 loading / 失败 / 取消三态；失败文案中文且给「去设置 / 重试」；快捷键在设置页只读展示并指引到扩展快捷键页。
- 词典卡（弹窗与气泡共用同一套排版节奏）：单词 + 可点发音的音标胶囊 → 中文释义 / 英英释义 / 词形变化 / 例句 / 词组，六个区块由设置裁剪；服务不提供的区块自动不渲染。

## 5. 技术架构

- Service Worker：唯一联网方；消息路由、右键菜单、快捷键、任务表、缓存、写历史。
- Content Script：页面 DOM 读写（划词/网页翻译），不发网络请求。
- 扩展页面（弹窗/设置/生词本）：React 渲染，直接用 `chrome.storage`。
- 通信：Port 协议（`translate` / `dict` / `check` / `polish` / `cancel` / `test` → `delta`（多引擎时带 `engineId`）/ `progress` / `engineDone` / `done` / `dictDone` / `checkDone` / `polishDone` / `testDone` / `error`），`requestId` 对齐；网页翻译的控制走一次性消息：弹窗 → `runtime.sendMessage` → SW 取当前标签页 → `tabs.sendMessage` → content script，进度反方向 `runtime.sendMessage` 广播回弹窗。
- 构建：一个 `scripts/build.mjs` 连跑三次 Vite（页面多入口三条：`popup` / `options` / `learning`、background ESM、content IIFE）。
- 权限：`storage / unlimitedStorage / scripting / activeTab / contextMenus`；`<all_urls>` 内容脚本；内置服务商（谷歌、MyMemory、百度、Azure、OpenAI、Gemini、xAI 等固定域名）写进 `host_permissions`，自定义 / 本地端点仍走 `optional_host_permissions` + 点击授权。

## 6. 服务商策略

服务分三类：**免费通道**（谷歌、MyMemory）、**需要密钥的机器翻译**（百度、微软 / 必应 Azure v3）、**AI 服务**（OpenAI 兼容，含 Gemini 兼容层与 Grok）；另有一组独立的**词典接口**（有道、Free Dictionary API，都免 Key），只服务单个单词的查询。

- 只用**启用且就绪**的服务：引擎列表只列可用的，未就绪的选中项标出并给「去配置」；翻译面板可多选并拖动排序（也可聚焦把手后按 ↑ / ↓），其余槽位单选。
- 多引擎作用于翻译面板与划词的句子翻译（同一个 `translateEngines` 列表）：勾几个就并发请求几个，每个引擎各自一张小卡、按勾选顺序排列、边生成边显示，单个失败只影响自己那张卡，全部失败才整体报错；划词气泡里每张卡的朗读、复制、收藏作用于该卡译文。划词在请求里显式传 `engineIds`；网页翻译与词典仍只跑主引擎/单个服务。
- 翻译面板里排在第一位的引擎是主引擎（`primaryTranslateEngine()`）：网页翻译与历史没显式指定引擎时用它，划词单靠这组列表的 `engineIds`，历史只记主引擎这一条。拖动排序会改变主引擎，网页翻译、历史以及检查/润色的自动兜底顺序随之变化，这是排序功能的预期行为。
- **没有失败降级**：引擎未配置或运行失败都直接报错，不会悄悄换成免费通道（早期版本有自动降级与「已自动降级」标记，已移除）。
- 检查 / 润色只能用 AI，自动模式 = 按引擎顺序找第一个可用 AI（翻译引擎是 AI 就用它），否则用第一个可用 AI。
- **思考强度按服务配置**（`reasoningEffort`，四档含空串）：「跟随模型默认」＝请求体不带 `reasoning_effort`，选了档位才下发。拍板理由是 OpenAI 兼容层对该字段的接受度不一致，默认带上会让原本能用的老模型或网关直接 400——宁可少一个优化项，也不能让服务无故打挂；档位只对这一家的翻译 / 检查 / 润色生效，不做跨服务统一。
- 网页翻译按量最大，默认走免费通道；切到 AI 时按段计费。
- 实测结论见 `providers.md`。

## 7. 数据与存储

全部 `chrome.storage.local`：`settings.v1`（载荷 version 2：`translateEngines` 多选引擎 + `services` 凭证表 + `dictionary` 词典开关/服务/展示项 + `aiProviders`；旧的 `mtEnabled` 与单个 `translateEngine` 在读取时自动迁移）、`history.v1`（最多 200 条，网页翻译不写入）、`cache.v1`（分片缓存，TTL 7 天、上限 1000 条、LRU，网页翻译按批命中）、`learning.v1`（生词卡片 + 每日复习次数 + 正确次数；卡片量小，暂不迁 IndexedDB）。
