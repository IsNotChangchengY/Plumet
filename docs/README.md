# 文档索引与维护规则

## 1. 文档地图

| 文档 | 写给谁 | 内容 | 主要更新时机 |
|---|---|---|---|
| `AGENTS.md`（项目根，不提交） | AI 编码助手、你自己 | 操作手册：命令、加载调试、目录、关键设计、代码约定、已知陷阱、验证清单、路线图 | 每次改动都检查一遍 |
| `README.md` | 使用者 | 当前能做什么、怎么装、怎么配 | 用户可见功能变化时 |
| `docs/design.md` | 你、接手的人 | 产品与技术总纲：定位、功能设计、荧光笔规范、UI/UX、架构、里程碑 | 设计取舍变化时 |
| `docs/ui-design.md` | 改界面、加组件的人 | UI 设计规范：设计变量（浅/深）、排版、圆角阴影、动效、组件、三处界面的结构与尺寸、主题实现、验收清单 | 改样式、设计变量或界面结构时 |
| `docs/providers.md` | 新增/维护服务商的人 | 服务商契约、新增三步、错误码、AI 调用细节、免费通道实测记录 | 接入或实测新服务商时 |
| `docs/guide/00` | 第一次做扩展的人 | 扩展是怎么跑起来的（四个运行环境） | 架构变化时 |
| `docs/guide/01` | 你 | 加载、调试、验证步骤 | 加载方式/验证流程变化时 |
| `docs/guide/02` | 你 | 代码地图与一次请求的旅程 | 文件增删、数据流变化时 |
| `docs/guide/03` | 你 | 常见错误对照（现象 → 原因 → 解决） | 每次踩到新坑时 |

## 2. 自迭代规则（每次增量/改动必做）

> **文档和代码在同一次改动里完成**，不允许「先写代码，下次补文档」。

### 2.1 改了什么 → 同步哪份

| 本次改了什么 | 必须同步更新 |
|---|---|
| 新增 / 删除 / 重命名源文件 | `AGENTS.md` 目录结构；`docs/guide/02` 代码地图 |
| 新增命令、脚本、依赖 | `AGENTS.md` 常用命令；用户可见的能力变化写进 `README.md` |
| 新踩到的坑、新的实测结论 | `AGENTS.md` 已知陷阱；如果是服务商相关，同时进 `docs/providers.md` |
| 接入新服务商、改错误码 | `docs/providers.md` |
| 设计取舍变化（数据流、呈现方式、交互语义） | `docs/design.md` 对应章节 |
| 改样式、设计变量、界面结构、新增 UI 组件 | `docs/ui-design.md` 对应章节；同时检查 `src/ui/theme.css` 与 `src/content/theme.ts` 两处变量是否同步 |
| 用户可见功能变化 | `README.md` 功能章节（只写现在能做什么） |
| 里程碑推进 | `AGENTS.md` 路线图；`docs/design.md` 里程碑表 |
| 测试数量变化 | `AGENTS.md` 常用命令里的数量 |
| 新增文档 | 本文档的「文档地图」 |

### 2.2 写法约定

- **删旧留新**：过时内容直接改掉或删掉，不要在旧说法后面追加新段落。
- **只改涉及段落**：不做整篇重排，保持 diff 可读。
- **路径、命令、数量必须与代码一致**：失效的路径会被 `pnpm docs:check` 抓到。
- **未经实测的结论标注 `（待验证）`**，不要写成既成事实。
- **教学文档（guide）跟着示例走**：功能变化后同步示例与「尚属正常的情况」清单。
- 教程类文档可以提到尚未实现的目标文件；带事实路径的三份文档（`AGENTS.md`、`docs/design.md`、`docs/providers.md`）不写不存在的路径。

### 2.3 一次改动算做完了吗

1. `pnpm check` 全绿（含 `pnpm docs:check`）。
2. `AGENTS.md` 的目录、命令、陷阱、状态都能对得上本次改动。
3. 第一次接手的人或 AI **只读这些文档**就能把项目跑起来，并知道坑在哪。
4. 本次改动的「为什么」已经落在 `docs/design.md`（取舍）或 `AGENTS.md`（操作事实）里。

## 3. 自动校验

```powershell
pnpm docs:check
```

- 校验 `AGENTS.md`、`docs/design.md`、`docs/providers.md` 里用反引号写出的 `src/ ...`、`scripts/ ...`、`docs/ ...` 等路径是否真实存在（`*` 通配会退化成检查目录）。
- 校验 `README.md` 与 `docs/**` 里的相对 Markdown 链接是否指向存在的文件。
- 校验失败通常意味着：改了文件名/删了文件，但文档没同步。

`pnpm check` 已经把这一步包含进去了，所以正常开发只要跑 `pnpm check` 就行。
